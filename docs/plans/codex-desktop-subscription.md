# Implementation plan for Codex on the bot computer

**Status** — Implemented. See [ADR 0030](../adr/0030-codex-desktop-chatgpt-plan.md) and the [setup guide](../guides/codex-desktop-setup.md).

## Scope

Run the official interactive `codex` command in the bot computer's terminal, following the [Claude desktop launcher](../adr/0012-interactive-claude-in-the-sandbox.md). Use the connected user's ChatGPT plan, meter input, output, and cached-input tokens per bot, and optionally apply a charge based on the workspace's model prices. A bot can have a desktop connection regardless of its chat model. The connected user uses it while holding the existing desktop control lock.

```text
Bot computer terminal → Codex CLI → per-bot egress proxy → OpenAI Responses API
                                        ↓
                              Bot usage and budget ledger
```

The control plane owns the OAuth connection and its renewal. The sandbox receives a provider profile and a public placeholder. Reuse the existing `llmproxy` response meter and workspace spending lock. OpenAI documents plan usage as a preview for eligible deployments. Confirm that the target deployment and account are eligible before enabling the feature. [OpenAI plan-usage overview](https://developers.openai.com/siwc/token-sharing-open-source) · [Self-hosted VM setup](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)

## 1. Verify the interactive CLI contract

- Build a candidate pinned Codex release in the sandbox and exercise `codex` under a pseudo-terminal against a loopback fake provider with external networking disabled. Check the initial prompt, a streamed reply, a local tool round trip, and a resumed session. Capture the methods, paths, request fields, headers, and terminal stream events needed by those flows.
- Configure a custom Responses provider with the proxy base URL, `env_key` for the placeholder, `requires_openai_auth = false`, and HTTP/SSE. Verify that the first launch reaches the terminal UI with these settings and that sessions can persist in the bot's existing home volume. Preserve the CLI's normal confirmation behavior.
- Check the captured requests against the ChatGPT plan contract, including `store: false`, `stream: true`, and inline context over HTTP. Resolve incompatible model discovery, compaction, and tool features through the pinned CLI configuration. Verify compatibility before fixing the launcher contract. [Codex provider configuration](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers) · [ChatGPT plan request requirements](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

## 2. Connect a ChatGPT plan to one bot

- Add a **ChatGPT plan for Codex** card to **Secrets & network**. Users with permission to manage the bot can start a connection for their own ChatGPT account. Store one active connection per bot, scoped by workspace and bot and bound to the connecting user. Show its status and provide **Reconnect** and **Disconnect** actions.
- Add a trusted workstation helper exposed as `make codex-login`. The card creates a short-lived, one-use pairing code bound to the authenticated user, workspace, and bot. The helper reads the code from an interactive prompt and runs the documented loopback OAuth flow with state, nonce, and PKCE. Validate the identity and plan-use grant before activation. For a remote self-hosted instance, transfer the selected registration over the protected helper-to-control-plane channel and preserve the instance's host ID. Keep credentials and pairing codes out of chat, command arguments, logs, and sandbox files. [OpenAI registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) · [Self-hosted registration transfer](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)
- Store session material with the existing envelope encryption. Serialize rotating refreshes for each connection and atomically replace the stored token set. Recheck bot permissions on completion and admission. Disconnect disables local access immediately and attempts upstream revocation. Distinguish expired or revoked credentials from temporary provider errors and exhausted plan allowances. [OpenAI session management](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) · [OpenAI errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery)

## 3. Wire the desktop launcher and metered proxy route

- Install the interactive launcher in the sandbox image alongside the official binary. Point its provider profile at a dedicated bot-local ChatGPT plan route, proposed as `POST /llm/openai-plan/v1/responses`. Read only connection availability from the proxy at launch. Keep the chat runner's credential resolution independent of the desktop connection.
- Bind the route to the proxy's trusted workspace and bot identity. At each admission, check the active connection, its owner against the current desktop control holder, bot pause state, and budget state. Use the existing environment state to check ownership and invalidate access when control is handed back or the connection is revoked. Derive these checks from server-side state. The placeholder identifies the launcher configuration and confers no access by itself.
- Forward compatible requests over TLS to the fixed OpenAI Responses endpoint. Apply explicit host blocks before forwarding. Strip sandbox-supplied credentials, inject the OAuth bearer token server-side, and reject redirects and alternate upstream routes. Keep direct model traffic subject to the existing egress restrictions. Stream successful responses using the existing writer and meter. Return stable errors for connection, plan, and budget failures. Map the relevant provider status and error code to safe messages and retain only a sanitized request ID for diagnostics. [Existing proxy handler](../../backend/internal/secrets/llmproxy/proxy.go) · [Per-bot proxy wiring](../../backend/cmd/egress-proxy/database.go)

## 4. Record tokens and apply optional budget charges

- Record each desktop inference request once against the bot and workspace with `turn_id` unset. Use the existing Responses SSE collector for input, output, and cached-input tokens. Treat a missing or incomplete terminal usage event as unknown usage. Expose per-bot totals by period on the bot's budget page and distinguish known usage from requests awaiting reconciliation. Cached input is included in total input. [Responses usage collector](../../backend/internal/secrets/llmproxy/meter.go)
- Add the workspace setting **Count subscription usage toward budgets**, off by default. Apply the same policy to Claude under [ADR 0011](../adr/0011-claude-subscription-outside-sandbox.md) and to desktop Codex. When enabled, price new requests using the configured provider and effective model ID. Apply the input rate to uncached input, the output rate to output, and the cache rate to cached input. Snapshot the charge policy and rates at admission so later edits apply to new requests. Require a matching price when admitting requests subject to a monetary cap.
- Store estimated subscription charges separately from provider-billed `cost_micros`. Count both toward the applicable budget commitment exactly once. Display the estimate as **Internal budget charge**, with provider spend presented separately. Desktop Codex contributes to bot and workspace limits. Group budgets cover chat-attributed usage. Extend the workspace-scoped budget API to return token totals and the internal charge with the appropriate permission checks. [Budget queries](../../backend/db/queries/budgets.sql) · [Budget API](../../backend/internal/api/budgets.go)
- Treat Codex plan requests as unbounded for preflight output cost while the endpoint omits support for `max_output_tokens`. Reuse per-request workspace spend serialization for charged requests subject to a cap. Check available budget before forwarding, settle once the stream finishes, then reevaluate before the next request. An already admitted request can exceed the cap. Persist an unknown charge when a request may have incurred usage and the final counts are unavailable. Apply the existing reconciliation policy to those charges. [Existing admission and settlement](../../backend/internal/budgets/meter.go) · [OpenAI preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

## 5. Verify and ship

| Area              | Acceptance checks                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Desktop           | The pinned image starts `codex` in a terminal, receives SSE, runs a local tool, and resumes a session. Usage is attributed to the bot with no chat turn, including when a chat turn exists in the database. Missing connection, another control holder, handback, pause, and unavailable proxy deny new plan requests.                                                                                          |
| Connection        | Cover invalid and missing inputs, unauthenticated and forbidden requests across the role matrix, cross-workspace `404`, declined consent, wrong account or scope, expired and replayed pairing, revoked sessions, concurrent refresh, and temporary OAuth failures. Fixtures verify that credential values never reach sandbox state, API responses, or logs.                                                   |
| Proxy             | A fake upstream verifies the method, path, approved headers, SSE completion, and credential injection. Reject unsupported route, method, transport, oversized payload, and redirect. Cover provider `429`, `503`, mid-stream errors, timeout, and cancellation. Exercise direct-provider egress denial and verify that explicit host blocks still apply.                                                        |
| Usage and budgets | Cover cached-input pricing, opt-in and opt-out, old usage rows, missing rates, unknown usage, no double counting, concurrent calls, settlement after cancellation, the request that crosses a cap, and rejection of the next request. Verify that Codex desktop usage never changes a chat group's budget.                                                                                                      |
| UI and release    | Cover connection and error states, permissions, token totals, and clear labeling of internal charges. Use `next-intl` and the existing styleguide. Run the sandbox contract tests and `make lint test` with mock OAuth and model endpoints. Verify the documented setup with the release images and update `Application.md`, the ADRs, `design/STYLEGUIDE.md`, and the setup guide before enabling the feature. |
